## 1. 环境准备

### 1.1 Python 与依赖
- 推荐 Python 3.12（本机已验证 3.12.2）。
- 依赖见 `requirements.txt`（已锁定"验证可用"版本）：Flask 3.1.3、Werkzeug 3.1.8、gunicorn 23.0.0、jieba 0.42.1、numpy 2.5.2、python-docx 1.2.0、pypdf 6.15.0、openpyxl 3.1.5、beautifulsoup4 4.15.0、requests 2.34.2、pyotp 2.10.0、qrcode 8.2、ldap3 2.9.1。

```bash
# 建议用受管 venv（推荐）
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 或本机已验证的隔离环境
/Users/ikingsmart/.workbuddy/binaries/python/envs/aikm/bin/python -m pip install -r requirements.txt
```

### 1.2 配置（.env）
- 复制 `cp .env.example .env`，按 `部署与运维手册.md` 填入真实密钥。
- 关键项：`AIKM_SECRET_KEY`（必填，生产随机值）、`AIKM_DB_PATH`、`AIKM_DEBUG=false`、`AIKM_LLM_*`、`AIKM_EMBED_*`、`AIKM_HTTPS`、`AIKM_MFA_*`、`AIKM_SSO_*`。
- 加载顺序：`.env` 由 `run.py`/`wsgi.py` 在导入 config 前调用 `config.load_dotenv()` 注入；脚本类（`seed_demo`/`init_data`/`import_eval`/`run_eval`）也已注入，保证与线上一致。

### 1.3 数据库
- 默认 `data/aikm.db`（SQLite）。可用 `AIKM_DB_PATH` 覆盖（测试隔离常用 `/tmp/aikm_*.db`）。
- 首次启动自动建表；老库升级走 `db.py` 的 `_migrate_columns()`。

## 3. 编码规范（硬性要求）

> 团队 .NET 背景，要求**逐行中文注释**，小白也能读懂。所有新增代码必须遵守。

- 每个文件头部 `# -*- coding: utf-8 -*-` + 模块 docstring 说明职责。
- 每个函数 docstring 说明"做什么 / 参数 / 返回 / 异常"。
- 关键逻辑行后随行中文注释解释"为什么"（如 PBKDF2 迭代次数、RRF 公式、权限过滤意图）。
- 命名：变量/函数小写下划线，常量全大写下划线；避免缩写歧义。
- 不允许裸 `except:`；区分可恢复与致命异常，失败路径给出可操作提示。
- 安全：所有 SQL 走参数化（`db.query/execute`，用 `?` 占位符），禁止字符串拼接。

## 4. 本地启动与调试

```bash
# 开发模式（Flask dev server，自动重载）
python run.py
# 或生产形态（gunicorn，更接近线上）
./start.sh
# 访问 http://localhost:5200
```

调试技巧：
- `AIKM_DEBUG=true` 可在页面看到堆栈（**仅本地**，生产必须 false）。
- 日志分级输出，关注 `[检索日志写入失败]`、`[BM25检索异常]`、`[向量检索降级]` 等降级提示——它们是非致命路径，说明某一路被优雅降级。
- 向量检索需要 `AIKM_EMBED_*` 有效密钥；无密钥时自动降级纯 BM25（`AIKM_EMBED_PROVIDER=hash` 可离线跑）。

## 5. 扩展指南（常见改造场景）

### 5.1 新增一个文档解析格式
1. 在 `app/ingest/parser.py` 增加 `parse_xxx(src) -> {"plain_text":..., "blocks":[...]}`。
2. 在 `parse_file()` 的分发字典里登记扩展名。
3. `config.ALLOWED_EXTENSIONS` 加入该扩展名。
4. 跑 `_verify_p0x` 或临时脚本验证切片/向量正常。

### 5.2 新增一个 API 端点
- **动作式**：在 `app/web/apis.py` 加 `@bp.route("/api/xxx")`；需鉴权加 `@auth.api_key_required` 或 `@auth.login_required`；返回统一 `jsonify({"ok":..,"data":..})`。
- **资源式（REST v1）**：在 `app/web/api_v1.py` 加端点，复用 `_ok()/_err()/_page_params()`，并在 `build_openapi_spec()` 登记，保证 `/api/v1/docs` 同步。

### 5.3 新增一张表 / 字段
1. 在 `app/db.py` 的 `SCHEMA_SQL` 加 `CREATE TABLE IF NOT EXISTS`（新表）或 `CREATE INDEX`。
2. **若是给老表加列**：不要写进静态脚本（老库会 no such column），改在 `_migrate_columns()` 里用 `ALTER TABLE ... ADD COLUMN` + 提交，再加索引。
3. 改动后跑 `scripts/_verify_*.py` 确认升级路径（`seed_demo` 会在真实库上触发迁移）。

### 5.4 切换模型（云 → 私有化）
- 改 `.env`：`AIKM_LLM_PROVIDER=ollama`、`AIKM_EMBED_PROVIDER=ollama` 及对应 BASE_URL；**零改码**。
- 切换 Embedding 后必须 `reindex_all()` 重建向量（旧维度向量会污染检索）。

### 5.5 接入 SSO 真实 IdP
- LDAP：`AIKM_SSO_ENABLED=true`、`AIKM_SSO_PROVIDER=ldap` + `LDAP_SERVER/BIND_DN/BIND_PASSWORD/USER_BASE/USER_FILTER`。
- OIDC：`AIKM_SSO_PROVIDER=oidc` + `OIDC_ISSUER/CLIENT_ID/CLIENT_SECRET/REDIRECT_URI`。
- `ldap3`/`requests` 缺失时 SSO 自动降级（应用照常启动），不影响其它功能。

## 6. 构建与发布

### 6.1 镜像构建
```bash
docker build -t aikm:production-test .   # Dockerfile 已加 HEALTHCHECK、.dockerignore
docker run -d -p 5400:5200 --env-file .env -v aikm_data:/app/data aikm:production-test
```
- 生产用 gunicorn `-k gthread -w 1 --threads 8`，单进程多线程适配 SQLite 写并发。
- 容器内端口 5200；`.env` 不进镜像（`.dockerignore` 排除）；健康检查探 `/login`。

### 6.2 一键部署（内网）
```bash
cp .env.example .env   # 填真实密钥
docker compose up -d --build
# 访问 http://<服务器IP>:5200
```
详见 `部署与运维手册.md`（含 Nginx HTTPS 反代片段、备份恢复、升级迁移）。

## 7. 常见坑与排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动 `ImportError: No module named pyotp` | 漏装 P2 依赖 | `pip install -r requirements.txt`（已含 pyotp/qrcode/ldap3/gunicorn） |
| 老库启动 `no such column: anchor` | 静态脚本引用 P1 才加的列 | 已在 `_migrate_columns` 修复；跑 `seed_demo` 触发迁移即可 |
| 向量检索无效但 BM25 正常 | Embedding 密钥无效/限流 | 看 `[向量检索降级]` 日志；换 `AIKM_EMBED_PROVIDER=hash` 离线跑 |
| 登录后不跳改密页 | 前端未处理 `must_change_pwd` | 已补 `/change-password` 与登录跳转 |
| REST 列表返回空 | 未带鉴权或 `doc_id` 无权限 | 带 `Authorization: Bearer <key>` 或登录会话；权限走数据层过滤 |
| diagrams.net 编辑界面空白 | 需联网加载 embed.diagrams.net | 内网离线需自托管或放开公网 CDN |
| API 调用 429 | 登录/接口触发限流 | 等待锁定窗口过期（默认 15min） |
