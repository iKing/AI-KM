| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 制定 | 庄金冬（规范指导）、王智（推进落地） |
| 生效日期 | 2026-08-15 |
| 适用范围 | 全公司各部门知识资产入库 |
| 复审周期 | 90 天 |

---

## 一、为什么要有这份规范

一句话：**AI 检索不准，九成不是模型问题，是知识本身没整理好。**

同一份集采政策，有人命名"文档1.docx"，有人命名"20250612 湖北省医用耗材集中带量采购实施方案（第三批）.docx"。前者进了库，AI 永远搜不到；后者进了库，AI 一搜就中。差别不在技术，在规范。

这份规范是 SG1 知识资产化的执行底座，也是 SG2 各类 AI 场景能否跑通的前置条件。

## 二、知识分类体系

### 2.1 一级分类（六大知识域，固定不可自建）

| 编码 | 一级分类 | 收录内容 | 主责部门 | 优先级 |
|---|---|---|---|---|
| `POLICY` | 政策法规库 | 国家/省市集采政策、招投标法规、医保目录、器械注册法规、政策解读 | 政策研究 | **P0** |
| `PROJECT` | 项目知识库 | 项目方案、投标文件、实施记录、验收材料、项目复盘 | 项目部 | **P0** |
| `CUSTOMER` | 客户与市场 | 客户常见问答、客户档案、竞品分析、行业研究、市场动态 | 市场/销售 | **P0** |
| `PRODUCT` | 产品与技术 | 产品手册、功能说明、API 文档、技术方案、架构设计、故障手册 | 技术部 | P1 |
| `PROCESS` | 制度与流程 | 公司制度、部门 SOP、审批流程、合同模板、表单模板 | 行政/各部门 | P1 |
| `TRAINING` | 培训与沉淀 | 培训课件、操作指南、经验分享、AI 应用案例 | 各部门 | P2 |

> P0 为 8 月底示范场景必须完成的高质量入库范围。

## 三、元数据字段规范

### 3.1 字段清单

| 字段 | 必填 | 格式要求 | 说明 | 反例 |
|---|:--:|---|---|---|
| **标题** | ✅ | 15-60 字，须含关键要素 | 见 3.2 命名法 | `方案.docx`、`最终版2` |
| **一级分类** | ✅ | 六大域之一 | 不可自建 | 自造"其他类" |
| 二级分类 | ⬜ | 报备编码 | 无合适项可留空 | — |
| **归属部门** | ✅ | 系统部门列表 | 决定检索可见范围 | — |
| **密级** | ✅ | 公开/内部/机密 | 见第五章 | 全填"公开" |
| **责任人** | ✅ | 真实姓名 | 内容准确性负责人、复审通知对象 | 填"公司"、"IT" |
| **生效日期** | ✅ | YYYY-MM-DD | 文件发布/签发日期 | 填上传日期 |
| 失效日期 | ⬜ | YYYY-MM-DD | 政策类**强烈建议填写** | — |
| 来源 | ⬜ | 机构名 / URL | 政策类**必填** | 空着 |
| 标签 | ⬜ | 3-8 个，逗号分隔 | 补充检索维度 | 一口气打 30 个 |
| 摘要 | ⬜ | 100-300 字 | 留空则系统自动生成 | — |

### 3.2 标题命名法（最重要的一条）

> **标题公式：`[地域/主体] + [时间] + [主题] + [文件类型]`**

标题是检索命中率最高的字段。一个好标题让 AI 一次命中，一个坏标题让文档永远沉底。

**✅ 正面范例**

| 分类 | 好标题 |
|---|---|
| POLICY | `湖北省 2025 年医用耗材集中带量采购实施方案（第三批）` |
| POLICY | `国家医保局 2025 年医保药品目录调整工作方案解读` |
| PROJECT | `武汉协和医院 SPD 项目实施方案 v2.1（2025-06）` |
| PROJECT | `2025 年上半年 XX 医院器械集采项目复盘总结` |
| CUSTOMER | `客户常见问答：集采平台数据对接常见 20 问` |
| PRODUCT | `智采器械信息网 API 接口文档 v1.0` |
| PROCESS | `采购合同审批流程 SOP（2025 修订版）` |

**❌ 反面范例与修正**

| 错误标题 | 问题 | 修正 |
|---|---|---|
| `方案.docx` | 无任何信息量 | `湖北省 2025 年医用耗材集采实施方案（第三批）` |
| `最终版-确定版-3.docx` | 版本号当标题 | 标题写内容，版本走版本字段 |
| `关于进一步加强相关工作的通知` | 全是虚词，不知所云 | `国家药监局关于加强医疗器械唯一标识（UDI）实施工作的通知` |
| `张三的文档` | 以人命名 | 按内容命名，责任人填字段 |
| `20250612` | 只有日期 | `2025-06-12 医保局带量采购价格联动通知` |
| `政策汇编（1-100页）` | 多主题混装 | 拆分为独立文档分别入库 |

### 3.3 内容质量红线（触碰即拒绝入库）

| # | 红线 | 判定 |
|---|---|---|
| 1 | 正文有效文字 < 200 字 | 系统自动拒绝 |
| 2 | 纯扫描件、纯图片、无可提取文本 | 系统自动拒绝（可走人工补摘要降级） |
| 3 | 与已有文档内容完全重复 | 系统哈希去重自动拦截 |
| 4 | 必填元数据缺失 | 系统自动拒绝 |
| 5 | 含个人身份证号、银行卡号等个人隐私 | 审核员人工拦截 |
| 6 | 未脱敏的客户报价、合同金额（除非标机密） | 审核员人工拦截 |
| 7 | 明显过期且无历史价值（如已废止政策未标失效） | 审核员退回补充失效日期 |
| 8 | 内容与所选分类明显不符 | 审核员退回改分类 |

## 四、文档结构规范（决定切片质量）

平台按标题层级切片，**有结构的文档检索准确率显著更高**。

### 4.1 结构要求

| 要求 | 说明 |
|---|---|
| 使用标题样式 | Word 中用"标题1/2/3"样式，**不要用加粗大字号冒充标题** |
| 层级不超过 4 级 | 过深难以定位 |
| 段落长度适中 | 单段 200-800 字为宜，避免万字长段 |
| 表格加表头 | 无表头的表格切片后语义丢失 |
| 图片加说明文字 | 图片内容 AI 读不到，需文字说明 |
| 术语首次出现给全称 | `UDI（医疗器械唯一标识）`，便于检索命中 |

### 4.2 正反对照

**✅ 好结构**
```
标题1  第一章 适用范围
标题2    1.1 适用产品类别
正文       本方案适用于以下医用耗材类别：……（300字）
标题2    1.2 适用医疗机构
正文       ……
标题1  第二章 采购规则
标题2    2.1 报价规则
正文       ……
```
→ 切片后每片携带章节路径 `第二章 采购规则 > 2.1 报价规则`，AI 能精确定位。

**❌ 坏结构**
```
正文  一、适用范围（加粗手打，非标题样式）
正文  本方案适用于……（连续 8000 字不分段，含 5 个主题）
```
→ 切片只能按字数硬切，语义被切断，检索命中后返回的片段答非所问。

## 五、密级判定标准

| 密级 | 判定标准 | 典型文档 | AI 问答 |
|---|---|---|---|
| **公开** `public` | 已对外发布或可对外发布 | 公开政策原文、产品宣传册、公开发表文章 | ✅ 参与 |
| **内部** `internal` | 公司内部流通，外泄无重大损失 | 项目方案、内部 SOP、客户 FAQ、培训材料 | ✅ 参与（默认） |
| **机密** `confidential` | 外泄造成商业损失或违约 | 客户合同、报价策略、核心算法、未公开投标文件、客户名单 | ❌ **默认不参与**，需显式授权 |

**判定口诀**：
> 能贴官网 → 公开；同事都能看 → 内部；泄露要担责 → 机密。
>
> **拿不准时按高一级处理。** 定高了可申请降级，定低了泄露无法挽回。

## 六、入库流程

```
贡献者上传/批量导入
      ↓
系统自动校验（元数据完整性 / 格式 / 大小 / 正文长度 / 内容去重）
      ↓  不通过 → 返回具体原因，贡献者修正后重提
      ↓  通过
系统解析切片 + 向量化
      ↓
提交审核（状态：待审核）
      ↓
审核员审核（内容准确性 / 分类正确性 / 密级合理性 / 隐私合规）
      ↓  退回 → 附退回理由
      ↓  通过
发布（可检索、可被 AI 调用）
      ↓
生命周期管理（到期复审 / 版本更新 / 过期下架）
```

### 6.1 各角色职责

| 角色 | 职责 | 时限要求 |
|---|---|---|
| 部门联络人（贡献者） | 本部门文档梳理、元数据填写、上传 | 按 SG1 时间表 |
| 审核员 | 3 个工作日内完成审核，退回须写明理由 | ≤3 工作日 |
| 责任人 | 对内容准确性负责，收到复审通知 15 日内处理 | ≤15 日 |
| 平台管理员 | 分类维护、权限配置、系统运维 | — |

### 6.2 批量导入操作

1. 整理文档到一个文件夹
2. 按模板填写 `metadata.csv` 元数据清单（模板见 `docs/templates/metadata_template.csv`）
3. 打包为 ZIP 上传，或放到服务器目录后扫描导入
4. 系统逐份校验，输出结果清单（成功 / 失败及原因）
5. 修正失败项后重新导入（已成功项自动跳过，不会重复）

**CSV 模板字段**：
```csv
文件名,标题,一级分类,二级分类,部门,密级,责任人,生效日期,失效日期,来源,标签
湖北集采方案.docx,湖北省2025年医用耗材集中带量采购实施方案（第三批）,POLICY,POLICY-PROVINCIAL,政策研究部,internal,张三,2025-06-12,2026-12-31,湖北省医保局,集采;医用耗材;湖北
```

## 七、质量分级与提质路线

| 等级 | 含义 | 判定 | 检索权重 |
|---|---|---|---|
| `verified` 已验证 | 审核员逐条校验，可直接供 AI 引用 | 人工标记 | ×1.2 |
| `normal` 常规 | 元数据合规、内容未逐条校验 | 审核通过默认 | ×1.0 |
| `draft` 待提质 | 仅完成入库，质量存疑（如降级入库、结构差） | 系统自动标记 | ×0.8，问答中标注"未验证" |

**提质路线（对应 SG1 三阶段）**
- 8 月底：示范场景关联知识 100% `verified`
- 10 月中：全量入库，允许大量 `normal`
- 12 月底：`draft` 清零，全量 ≥ `normal`，核心域 `verified`

## 八、持续更新机制

| 机制 | 规则 |
|---|---|
| 到期复审 | 失效日期到期前 15 天通知责任人 |
| 周期复审 | POLICY 90 天 / PROJECT 180 天 / 其他 365 天 |
| 版本更新 | 同名文档更新自动升版本，保留历史可回溯 |
| 过期下架 | 软删除，不参与检索但审计可查 |
| 缺口补齐 | 每周导出"零结果查询清单"，指导补充知识空白 |
| 季度盘点 | 各部门核对本部门知识资产完整性 |

## 九、常见问题

**Q：一份 200 页的政策汇编怎么入库？**
A：拆。每个独立政策一份文档。汇编整体可另存一份作索引文档。

**Q：Excel 数据表怎么入库？**
A：结构化数据表（如价格表）建议转为说明性文档描述其内容与用途，原表作为附件。纯数字表格 AI 检索价值低。

**Q：外部网页资料怎么入库？**
A：另存为文档，来源字段填原始 URL，标注抓取日期。

**Q：草稿、过程稿要入库吗？**
A：不要。只入最终版。过程稿留在个人/部门空间。

**Q：同一政策有原文和解读，怎么处理？**
A：分两份入库。原文 `POLICY-PROVINCIAL`，解读 `POLICY-INTERPRET`，通过标签关联。

**Q：文档很长要不要手动切分？**
A：不用。平台按标题层级自动切片。你要做的是**把标题层级用对**。
