## 1. 设计目标与约束

| 维度 | 设计目标 | 对应需求 |
|---|---|---|
| 检索准确 | 混合检索（BM25 + 向量）融合排序，权限前置过滤 | FR-4、NFR-1 |
| 可信可控 | 答案必须带引用、无结果明确拒答、机密默认隔离 | FR-5、NFR-5/6 |
| 零重型依赖 | 不引入 LangChain 等黑盒框架，链路全可读 | NFR-2 |
| 可插拔模型 | 换 LLM/Embedding 只改配置不改代码 | FR-9、NFR-4 |
| 单机可跑 | SQLite + 本地向量，单机 Docker Compose 一键部署 | NFR-3 |
| 安全闭环 | 密码加盐哈希、数据层权限隔离、审计只增不改 | FR-1、FR-11、NFR-7 |

## 2. 总体架构

### 2.1 分层架构

```
┌──────────────────────────────────────────────────────────────────┐
│  表现层（Web UI）  pages.py → Jinja2 模板 → 浏览器                    │
│  检索框 / 问答 / 上传 / 审核台 / 看板 / 管理后台 / MFA / 画图         │
├──────────────────────────────────────────────────────────────────┤
│  接口层（REST）                                                     │
│   · 动作式 /api/*      （apis.py，会话 + API Key 双鉴权）           │
│   · 资源式 /api/v1/*   （api_v1.py，标准 REST + OpenAPI）           │
│   · 页面路由 /, /search, /admin, /doc/<id> ...（pages.py）          │
├──────────────────────────────────────────────────────────────────┤
│  业务层（app/）                                                      │
│   ├─ ingest/   解析 → 校验 → 切片 → 向量化 → 入库（pipeline.py）    │
│   ├─ search/   BM25 ∥ 向量 → RRF 融合 → 质量加权 → 权限过滤        │
│   ├─ rag.py     检索 → 组装上下文 → LLM → 引用溯源 → 拒答判定       │
│   ├─ auth.py    认证 / RBAC / 数据层可见性 / API Key / 限流         │
│   ├─ mfa.py     TOTP 多因子（P2）                                   │
│   ├─ sso.py     LDAP / OIDC 单点登录（P2）                          │
│   ├─ audit.py   全链路审计（只增不改）                              │
│   └─ eval.py    检索质量评测集与跑分                                │
├──────────────────────────────────────────────────────────────────┤
│  适配层（providers/）  可插拔                                       │
│   ├─ llm.py     DeepSeek / OpenAI 兼容 / Ollama                     │
│   └─ embedding.py  SiliconFlow / OpenAI / Ollama / hash(离线降级)  │
├──────────────────────────────────────────────────────────────────┤
│  存储层                                                            │
│   ├─ SQLite       业务数据 + FTS5 全文索引 + 审计（单文件 data/aikm.db）│
│   ├─ 向量索引      chunk_vectors 表，float32 BLOB（numpy 内存检索） │
│   └─ 文件存储      data/uploads（按 年-月 分目录 + UUID 防覆盖）     │
└──────────────────────────────────────────────────────────────────┘
```

### 2.2 部署架构

```
       互联网/办公网
            │
   ┌────────┴─────────┐
   │  Nginx 反向代理    │  可选：HTTPS 终止 / 限流 / 静态缓存
   │  （建议，非必须）  │
   └────────┬─────────┘
            │ http://host:5200
   ┌────────┴─────────┐
   │  Docker 容器       │
   │  gunicorn -k gthread │ 单进程多线程（适配 SQLite 写并发）
   │  -w 1 --threads 8   │ HEALTHCHECK 探活 /login
   │  wsgi:app           │
   └────────┬─────────┘
            │ 挂载命名卷
   ┌────────┴─────────┐
   │  /app/data 持久卷  │  SQLite + uploads + index
   └──────────────────┘
```

设计取舍：内网规模下 **单机 + SQLite** 运维成本最低（拷走目录即迁移）；并发读写通过 gunicorn 单 worker 多线程 + SQLite 串行写避免锁竞争。当数据量或并发超过阈值（见 NFR-4）再升级 Postgres + 向量库，DAO 层已做隔离。

## 3. 技术选型与理由

| 选型 | 用途 | 理由 | 升级路径 |
|---|---|---|---|
| Python 3.12 + Flask 3.1 | Web 框架 | 团队已有 Flask 经验（智采日报），运维一致 | — |
| gunicorn 23（gthread） | WSGI 生产服务器 | 取代 Flask dev server，稳定/并发达标 | 多 worker（需共享存储） |
| SQLite + FTS5 | 业务库 + 全文索引 | 零运维、单文件备份、内网友好 | → PostgreSQL + pgvector |
| numpy 2.x | 向量余弦检索 | 10 万切片内毫秒级；无则纯 Python 降级 | → Milvus / Qdrant |
| jieba | 中文分词 | FTS5 不识中文，需预分词 | — |
| RRF 融合 | 多路召回排序 | 只看排名不用调参，鲁棒 | → 加 reranker |
| pyotp + qrcode | MFA(TOTP) | RFC6238 标准实现，SVG 二维码 | — |
| ldap3 + requests | SSO | 懒加载，缺依赖优雅降级 | — |
| 解析库 | docx/pdf/xlsx/html | python-docx / pypdf / openpyxl / bs4 | 注册新解析器 |

> **不用 LangChain**：检索与 RAG 链路完全自研、可读可调，便于定位与合规审计（NFR-2/6）。

## 4. 模块设计

### 4.1 ingest（入库流水线）— `app/ingest/`
- `parser.py`：`parse_file()` 统一入口，按扩展名分发到 docx/pdf/xlsx/html/md/txt 解析器；返回 `{plain_text, blocks}`（blocks 含标题层级）。
- `chunker.py`：`chunk_blocks()` 按语义边界切分，保留 `heading_path`（章节路径）与生成 `anchor`（段落锚点）；`make_summary()` 自动摘要。
- `pipeline.py`：`ingest_file()` 主流程——**元数据校验 → 文件落盘 → 解析 → 质量红线 → 哈希去重 → 切片 → 写 FTS → 向量化（失败降级） → 解析交叉引用 [[…]] → 进待审**；`ingest_batch()` 单份失败不中断整批；`reindex_document/all()` 重建索引（FR-9.3）；`update_document()/rollback_document()` 在线编辑与版本回滚（P0-2）。
- 关键不变量：正文权威源 `body_text` 与编辑器读写文本一致，保证版本 diff/回滚不漂移。
- **富文本双存（编辑器升级）**：`update_document()` 若收到 `html`（Quill 产出），先用 `app/htmlutil.sanitize_html()` 白名单净化得到 `body_html`，再用 `html_to_text()` 剥标签得到纯文本 `body_text`（检索/切片/diff 权威源不变）；`documents.body_html` 与 `doc_versions.body_html` 双存，回滚可还原富文本。`app/htmlutil` 为零依赖（仅标准库 `html.parser`），避免引入第三方净化库。

### 4.2 search（检索引擎）— `app/search/`
- `engine.py`：`search()` 主入口，流程——
  1. `_build_scope_sql()` 调用 `auth.visibility_filter` 构造**数据层权限 + 业务过滤** SQL（无权限文档从源头排除，非前端隐藏）；
  2. `_bm25_recall()` FTS5 关键词召回（异常降级）；
  3. `_vector_recall()` 余弦相似度语义召回（numpy 加速；向量失败降级纯 BM25）；
  4. `_rrf_fuse()` 倒数排名融合（score = Σ 1/(k+rank)）；
  5. 质量加权（verified×1.2 / normal×1.0 / draft×0.8）；
  6. 截断返回 + 高亮 + 锚点。
- `tokenizer.py`：jieba 预分词（`tokenize_to_string` / `build_fts_query` / `highlight_terms`）。

### 4.3 rag（问答编排）— `app/rag.py`
三条红线（FR-5）：有据可依、必须溯源、无结果拒答。
- `answer()`：机密开关校验（`can_view_confidential` + 审计留痕）→ 混合检索 → 低分/空结果触发 `NO_ANSWER_TEXT` 拒答 → 组装上下文（`build_context` 标注未验证）→ 调 LLM（流式/非流式）。
- 降级：LLM 不可用时返回检索原文片段（`degraded`），绝不编造（NFR-1）。
- 会话管理：`chat_sessions` / `chat_messages`，多轮上下文取最近 `RAG_HISTORY_TURNS` 轮；`save_feedback()` 反馈可沉淀为评测用例。

### 4.4 auth（认证鉴权）— `app/auth.py`
- 密码：`hash_password()` PBKDF2-SHA256（20 万次迭代）+ 每用户随机盐；`verify_password()` 用 `hmac.compare_digest` 防时序攻击；`validate_password()` 策略（≥8 位且含字母+数字）。
- 会话：`login_session()` 写签名 Cookie（永久会话，超时 8h）；`current_user()` 用 `g` 做请求级缓存。
- RBAC：`login_required` / `role_required` / `admin_required` 装饰器（API 返回 401/403 JSON，页面重定向）。
- 数据层隔离：`visibility_filter()` 生成 `密级红线 AND (创建人 OR (inherit 且 部门/公开) OR (restricted 且 文档级白名单))` 的 WHERE 条件，是所有文档查询的统一入口（核心安全函数）。**关键修正**：`restricted` 模式下「本部门匹配」不再自动放行，必须命中 `doc_acl` 白名单，真正实现"私有文档"语义；密级红线对全部路径一律生效（ACL 无法放宽密级）。
- 编辑权判定：`can_edit_doc()` 统一覆盖「角色规则 + 文档级 ACL 的 `view_edit` 授权」，替换原先散落的 `role_required` 装饰器，使编辑/标签/回滚等接口共用同一闸门。
- API Key：`create_api_key()` 只存哈希、明文仅返回一次；`api_key_required` 装饰器同时支持 `Bearer` 头与已登录会话。
- 防护：`login_rate_check()` 滑动窗口限流（账号+IP，5 次失败锁 15 分钟，返回 429）。

### 4.5 mfa / sso（P2 安全增强）
- `mfa.py`：`generate_secret()` Base32 密钥、`qr_svg()` 内联二维码、`verify_code()`（valid_window=1）、`generate_backup_codes()`（8 位备用码）；登录改两步（`/api/login` → 密码过暂存 `pending_mfa_user_id` → `/api/login/mfa` 校验动态码/备用码）。
- `sso.py`：`ldap3`/`requests` 全部懒加载，缺依赖时 LDAP 功能降级但应用照常启动；`authenticate_ldap()` 服务账号搜索+用户 DN 绑定；`oidc_*` discovery+授权+code 换 token+userinfo；按 username/email 关联本地账号，可自动建号。

### 4.6 audit（审计）— `app/audit.py`
- `log(action, user_id, ip, detail, result, sensitive)` 全链路留痕；动作码表 `ACTIONS`（含 mfa_enable / sso_login / diagram_save 等）。
- **只增不改**：应用层无 DELETE 路径（NFR-6/FR-11.3）；`search_logs()` 支持按动作/关键词/日期查询导出。

### 4.7 eval（质量评测）— `app/eval.py`
- 评测集（问题 + 金标准文档）→ 跑分（Recall@K / MRR / 命中率）→ 留档对比（`eval_runs` / `eval_results`），支撑"准确率 ≥ 90%"客观举证（FR-6）。

### 5.1 表清单（26 张）

核心业务：departments、users、documents、doc_versions、chunks、chunk_vectors、chunks_fts(虚表)、tags、doc_tags、doc_links、doc_comments、doc_diagrams、categories_l、knowledge_spaces、settings。

评测与对话：eval_cases、eval_runs、eval_results、chat_sessions、chat_messages。

### 5.2 核心表字段（节选，全量见 SRS 7.2）

**documents**（文档主表）
`id, title, category_l1, category_l2, department_id, space_id, security_level(public/internal/confidential), quality_level(verified/normal/draft), owner, effective_date, expire_date, next_review_at, source, summary, status(uploaded→…→published/rejected/archived), reject_reason, content_hash, file_path, file_name, file_ext, file_size, content_length, chunk_count, body_text(正文权威源), body_html(净化富文本), version, parse_error, created_by, reviewed_by, reviewed_at, created_at, updated_at, visibility_mode(inherit/restricted, 默认 inherit), edit_lock_user, edit_lock_at, edit_lock_name(并发编辑锁三列)`

**doc_acl**（文档级细粒度权限白名单，P 完整版补齐）
`id, doc_id, principal_type(user/role), principal_id, perm(view/view_edit), created_by, created_at` — 仅 `restricted` 模式下生效；`idx_acl_doc`/`idx_acl_principal` 两索引加速 `visibility_filter` 子查询。

**chunks**（检索最小单元）
`id, doc_id, seq, heading_path, anchor, content, char_count, created_at`

**chunk_vectors**（语义检索）
`chunk_id PK, doc_id, dim, model, vector(BLOB float32), created_at` — 单独建表便于换模型整表重建。

**users**（含 MFA 扩展列）
`…, mfa_secret, mfa_enabled, mfa_backup`（老库升级由 `_migrate_columns` 补列）

### 5.3 索引与迁移
- 高频过滤字段建索引：`idx_doc_status/cat/dept/sec/hash/review`、`idx_chunk_doc`、`idx_vec_doc`、`idx_link_*`、`idx_comment_doc`。
- `anchor` 列索引 `idx_chunk_anchor` **不在**静态建表脚本里（老库可能无该列），改由 `_migrate_columns()` 在确认列存在后创建——避免"老库升级即崩"。
- 迁移原则：所有 schema 变更走 `SCHEMA_SQL` 幂等建表 + `_migrate_columns()` 补列/补索引，保证 `data/` 目录拷到新版本即可平滑升级。

## 6. 关键流程设计

### 6.1 登录 + MFA（两步）
```
用户输入账号密码 → /api/login
  ├─ 认证失败 → 记审计 + 失败计数 + 限流
  └─ 认证成功
       ├─ 未开 MFA → 直接 login_session → 200
       └─ 已开 MFA → 暂存 pending_mfa_user_id → 返回 {mfa_required:true}
                  → 用户输动态码 → /api/login/mfa → verify_code/备用码 → login_session
强制改密：登录成功且 must_change_pwd=1 → 前端跳转 /change-password
```

### 6.2 混合检索
见 4.2：`scope SQL → BM25 ∥ 向量 → RRF → 质量加权 → 截断`。两路任一失败均降级，不整链路失败。

### 6.3 RAG 问答
见 4.3：机密开关校验（记审计）→ 检索 → 低于 `RAG_MIN_SCORE` 或空 → 拒答 → 否则组装上下文（标注未验证）→ LLM（失败降级原文）。

### 6.4 入库状态机（FR-3.5）
`uploaded → parsing → parsed → pending_review → published / rejected → archived(下架软删)`
审核员在 `/review` 批准/退回；下架保留审计痕迹，不参与检索。

### 6.5 权限隔离（数据层，FR-1.4/NFR-7）
`visibility_filter()` 统一产出：`密级∈许可 AND (创建人 OR (inherit 且 已发布且 本部门/公开) OR (restricted 且 文档级白名单命中))`，检索/列表/详情/评论全部复用，越权文档从源头排除。`restricted` 文档即便在同部门也需显式授权才可见（修复"私有文档泄漏"）。

### 6.6 SSO（P2）
LDAP：服务账号搜索用户 → 用户 DN 绑定校验密码 → 关联/自动建本地账号。
OIDC：`/api/sso/oidc/authorize` 跳转 IdP → 回调 `code` 换 token+userinfo → 登录。

### 6.7 并发编辑锁（FR-12，P 完整版补齐）
```
进入编辑页 → POST /api/documents/<id>/lock
  ├─ 抢到（空闲 / 自己已持 / 锁已超时 TTL）→ 200 + expires_at，前端启动心跳续期
  └─ 被他人有效持有 → 409 + held_by_name，前端降级为只读预览
保存成功 → 主动 DELETE /lock 释放；掉线/关页 → beforeunload 释放；超 TTL 自动失效可被抢占
保存时校验 edit_lock_blocking → 仍被他人持有则返回 409，杜绝互相覆盖
```

### 6.8 文档服务端导出（FR-13，P 完整版补齐）
- Docx：`app/export_docx.py` 用 python-docx 还原 h1–h6/段落/有序无序列表/引用/代码块/表格/图片(`/uploads/` 防 SSRF)/超链接；经 `io.BytesIO` 内存输出。
- PDF：`app/export_pdf.py` 用 reportlab platypus + 内置 CID 字体 `STSong-Light`（中文免外部字体文件）渲染同结构内容。
- 两者均复用 `_doc_export_meta()` / `_doc_export_html()`（优先 `body_html`，否则 `body_text` 兜底），且先过 `visibility_filter`（无权限 404）。

### 6.9 文档级细粒度权限（ACL，FR-14，P 完整版补齐）
```
创建人/管理员 → PUT /api/documents/<id>/acl  {visibility_mode, entries[]}
  visibility_mode: inherit（默认）| restricted（私有/受限）
  entries[]: {principal_type:user|role, principal_id, perm:view|view_edit}
读取：GET /acl 返回模式+明细+可选用户/角色；可见性由 visibility_filter 的 restricted 分支实时生效
授权 view_edit 的主体可在前端直接编辑该文档（can_edit_doc 命中 ACL）
```

## 7. 接口设计

| GET | /comments?doc_id= | 评论列表 |
| GET | /users | 用户列表（管理员） |
| GET | /audit | 审计日志（管理员） |

### 7.2 动作式 /api/*（会话 + API Key）

`/ /search /ask /upload /review /doc/<id> /doc/<id>/edit /doc/<id>/draw /doc/<id>/print /spaces /dashboard /admin /audit /mfa/setup /change-password /api/v1/docs /logout`

## 8. 安全设计（NFR-7）

| 层面 | 设计 |
|---|---|
| 认证 | PBKDF2-SHA256 20 万次迭代 + 随机盐；登录失败滑动窗口限流（429） |
| 会话 | 签名 Cookie，永久会话 8h 超时；HTTPS 下标记 Secure + HSTS |
| 授权 | RBAC + 数据层可见性过滤（统一入口，非前端隐藏） |
| 注入 | 全部参数化 SQL，零字符串拼接 |
| 上传 | 扩展名白名单 + 大小限制（50MB）+ 文件名消毒（防穿越）+ 内容哈希去重 |
| 密钥 | API Key 只存哈希；`.env` 在 `.gitignore`；`SECRET_KEY` 未配则随机并告警 |
| XSS | Jinja2 自动转义；用户内容不 innerHTML 直出 |
| 响应头 | CSP / X-Frame-Options / X-Content-Type-Options / Referrer-Policy |
| 审计 | 全链路只增不改；机密访问单独标记可筛选 |
| 机密 | 默认不进 AI 上下文，需显式开关并记审计 |

## 9. 可扩展性与升级路径（NFR-4）

| 扩展点 | 机制 | 操作 |
|---|---|---|

## 10. 设计决策记录（ADR 摘要）

| 决策 | 选择 | 理由 |
|---|---|---|
| 检索融合 | RRF（非加权求和） | 免调参、鲁棒 |
| 向量存储 | SQLite BLOB + numpy 内存检索 | 零运维、万级够用 |
| 权限隔离位置 | 数据层 WHERE（非前端隐藏） | 防绕过泄露 |
| 内容权威源 | body_text 与编辑器一致 | 版本 diff/回滚不漂移 |
| MFA 策略 | 用户自愿开启 | 避免无扫码设备用户被锁死 |
| 生产服务器 | gunicorn 单 worker 多线程 | 适配 SQLite 写并发 |
| 老库升级 | 迁移函数补列/补索引 | 防 no such column 崩溃 |
