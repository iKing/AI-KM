# AI-KM 知识管理平台 · 部署与运维手册

> 适用对象：负责把 AI-KM 部署到内网并日常运维的管理员 / 运维同事。
> 目标：照着做就能在可信局域网内跑起一套**生产级**知识库，并完成备份、升级、排障。

---

## 一、架构与运行方式

- **应用**：Flask + WSGI（生产用 gunicorn，多线程 `gthread` 模式，单进程适配 SQLite）
- **数据**：SQLite 单文件（`data/aikm.db`）+ 上传文件（`data/uploads`）+ 向量缓存（`data/index`）
- **部署形态**：Docker 镜像（非 root 用户 `aikm` 运行，内置健康检查），docker-compose 一键编排
- **端口**：默认 `5200`（避开同机 5100 智采日报服务）

> 说明：SQLite 在中小团队（数十人并发检索/问答）下完全够用。若未来并发量显著上升，
> 可将 `db.py` 的数据层切换到 Postgres（接口已隔离，工作量可控），gunicorn 再相应提高 worker 数。

## 二、Docker Compose 一键部署（推荐）

### 1. 准备环境
```bash
# 服务器需预装 Docker 与 docker compose 插件（Docker 20.10+ 自带）
docker --version
```

### 2. 准备配置
把项目拷到服务器后，复制环境变量模板并填写：
```bash
cp .env.example .env
vi .env            # 至少修改下面两项
```
**必改项**：
- `AIKM_SECRET_KEY`：会话签名密钥，**务必改成随机长字符串**。
  生成：`python -c "import secrets;print(secrets.token_hex(32))"`
  未设置时应用会临时随机生成（每次重启所有用户登录态失效），仅限本地临时演示。
- `AIKM_LLM_API_KEY` / `AIKM_EMBED_API_KEY`：模型密钥。
  若暂时没有外网密钥，把 `AIKM_EMBED_PROVIDER=hash` 即可启用**本地离线语义检索**（零 token 成本，效果略弱但保证可跑）；问答降级为原文片段引用。

> 其他如端口、MFA/SSO 开关、部门默认名等一般保持默认即可，详见文末「配置速查」。

### 3. 启动
```bash
docker compose up -d --build
docker compose ps        # 确认 aikm 状态为 healthy（HEALTHCHECK 探活 /login）
docker compose logs -f   # 观察启动日志
```
访问 `http://<服务器IP>:5200`。

### 4. 首次登录与强制改密
- 默认管理员：`admin / Admin@123456`
- **首次登录会被强制跳转「修改密码」页**，必须先设置新密码才能进入系统（安全基线要求）。
- 管理员进入「管理后台 ⚙️」建部门、建账号、分配角色；详见《用户使用指南》与《知识分类标准与入库规范》。

## 三、生产安全要点

### 3.1 上 HTTPS（强烈建议）
内部虽是可信局域网，但账号密码与 Cookie 明文传输仍有被嗅探风险。建议前方加一层 Nginx 反代做 TLS：

```nginx
server {
    listen 443 ssl;
    server_name km.corp.com;
    ssl_certificate     /etc/nginx/ssl/km.crt;
    ssl_certificate_key /etc/nginx/ssl/km.key;

    location / {
        proxy_pass http://127.0.0.1:5200;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;   # 必须，应用据此识别 HTTPS
    }
}
```
并在 `.env` 设 `AIKM_HTTPS=true`，应用会：
- 会话 Cookie 标记 `Secure`（仅 HTTPS 传输）
- 启用 `HSTS` 响应头（强制浏览器只走加密连接）

### 3.2 已内置的安全能力
- **会话 Cookie**：`HttpOnly` + `SameSite=Lax`，HTTPS 下 `Secure`
- **响应头**：`X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: no-referrer`、基础 `Content-Security-Policy`
- **登录暴力破解防护**：单「账号+IP」15 分钟内连续失败 5 次即临时锁定 15 分钟（返回 429）
- **密码强度**：长度 ≥ 8 且同时含字母与数字
- **MFA（TOTP）**：用户在「🔐 我的安全」页可自愿扫码开通，登录需动态码 + 备用码应急
- **SSO/LDAP/OIDC**：企业目录对接（配置门控，缺依赖优雅降级）
- **权限数据层过滤**：无权限文档从 SQL 层就被排除，前端的"隐藏"只是体验
- **审计日志**：关键动作（登录、改密、审核、删除类、SSO、MFA）全程留痕，无删除接口

### 3.3 容器权限
镜像内以非 root 用户 `aikm`（uid 10001）运行，降低容器逃逸影响面。
数据用**命名卷** `aikm_data` 持久化，卷权限与容器内用户一致，无 UID 错配问题。

## 四、数据备份与恢复

数据全部在命名卷 `aikm_data`（`/app/data`）。备份即备份该卷：

```bash
# 备份（停服或不停服均可，SQLite 小库建议停服一致性最佳）
docker compose stop aikm
docker run --rm -v aikm_aikm_data:/data -v $(pwd):/backup busybox \
  tar czf /backup/aikm_backup_$(date +%F).tar.gz /data
docker compose start aikm

# 恢复
docker compose stop aikm
docker run --rm -v aikm_aikm_data:/data -v $(pwd):/backup busybox \
  tar xzf /backup/aikm_backup_YYYY-MM-DD.tar.gz -C /
docker compose start aikm
```
> 卷名实际为 `<compose项目名>_aikm_data`（默认项目名即目录名 `aikm`）。用 `docker volume ls` 确认。

## 五、升级（代码更新 / 版本迭代）

AI-KM 的数据库迁移是**向前兼容、幂等**的（`db._migrate_columns` 自动补列、补表）：
```bash
git pull                 # 拉取新代码
docker compose up -d --build   # 重建镜像并重起，启动时自动迁移旧库
docker compose ps       # 确认 healthy
```
- 升级不删数据卷，**数据库结构会自动补齐**（如新增 MFA 列、anchor 列等）。
- 升级后建议跑一遍冒烟：`docker compose exec aikm python scripts/seed_demo.py`（幂等，仅做权限断言与功能冒烟）。

## 六、配置项速查（.env）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `AIKM_HOST` / `AIKM_PORT` | `0.0.0.0` / `5200` | 监听地址与端口 |
| `AIKM_DEBUG` | `false` | 生产务必 false |
| `AIKM_SECRET_KEY` | 临时随机 | 生产务必固定随机值 |
| `AIKM_HTTPS` | `false` | 前方有 TLS 时设 true |
| `AIKM_SESSION_HOURS` | `8` | 会话有效期 |
| `AIKM_EMBED_PROVIDER` | `siliconflow` | 无外网改 `hash` 走本地离线 |
| `AIKM_LLM_PROVIDER` | `deepseek` | 私有化改 `ollama` |
| `AIKM_PASSWORD_ITERATIONS` | `200000` | 密码哈希迭代次数 |
| `AIKM_LOGIN_MAX_FAIL` / `_LOCK_MIN` / `_FAIL_WINDOW` | `5` / `15` / `15` | 登录限流阈值 |
| `AIKM_MFA_ENABLED` | `true` | MFA 总开关 |
| `AIKM_SSO_ENABLED` / `AIKM_SSO_PROVIDER` | `false` / `ldap` | SSO 开关与协议 |
| `AIKM_API_V1_PREFIX` | `/api/v1` | 标准 REST 前缀 |
| `AIKM_EDIT_LOCK_ENABLED` | `true` | 并发编辑锁总开关 |
| `AIKM_EDIT_LOCK_TTL` | `300` | 锁有效秒数（超时自动失效可被抢占） |
| `AIKM_EDIT_LOCK_HEARTBEAT` | `60` | 前端心跳续期间隔（秒） |
| `AIKM_EDIT_LOCK_CHECK_SAVE` | `true` | 保存时是否校验锁（被他人占用返回 409） |
| `AIKM_ACL_ENABLED` | `true` | 文档级细粒度可见权限（受限/私有）总开关 |

完整清单见 `.env.example`。

## 七、故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 启动即退出 / 报 `ImportError: No module named 'pyotp'` | 依赖未装全 | 确认 `requirements.txt` 含 `pyotp/qrcode/ldap3/gunicorn`，重 `docker compose up -d --build` |
| `/login` 返回 500 | 模板或配置错误 | `docker compose logs` 看堆栈；多为 `.env` 缺失或配置项异常 |
| 上传文档报「内容过短」 | 正文 < 200 字红线 | 补充正文或调整 `AIKM_MIN_CONTENT_LENGTH` |
| AI 问答只返回原文片段 | 向量服务 401 / 无密钥 | 设 `AIKM_EMBED_PROVIDER=hash` 启用本地检索，或填正确密钥 |
| 登录提示「尝试次数过多」 | 触发暴力破解锁定 | 等 15 分钟，或重启容器清空内存限流（限流为进程内，重启即清） |
| 老库升级启动报 `no such column` | 旧 schema 缺列 | 已修复为自动迁移；若仍报，删 `data/*.db-wal/shm` 后重启触发迁移 |
